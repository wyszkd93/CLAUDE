# 크리스마스 트리 — HTML 캔버스 버전

브라우저에서 돌아가는 회전 크리스마스 트리입니다. 글자 8,500개로 나무를 만들고, 줄기에서 바깥으로 자란 뒤 황금 전구 줄·장식 공·반짝이는 전구·빛나는 별이 붙습니다. **`index.html` 파일 하나**가 전부이고 외부 라이브러리와 네트워크가 필요 없습니다(더블클릭해서 열면 됩니다).

## 열기

`index.html`을 브라우저로 열면 됩니다. 공유하려면 이 파일 하나만 보내거나 아무 정적 호스팅(GitHub Pages 등)에 올리세요.

| 조작 | 동작 |
|---|---|
| `Space` | 일시정지 / 재생 |
| `R` | 처음부터(다시 자라는 모습) |
| `H` | HUD(시간·회전각·글자 수) 켜기/끄기 |
| `F` | 전체 화면 |
| 오른쪽 아래 ⚙ | 글자, 글자 수, 전구 수, 회전 속도 바꾸기 |

주소 뒤에 인자를 붙여 같은 나무를 공유할 수 있습니다.

```
index.html?text=HAPPY%20NEW%20YEAR&letters=12000&lights=250&spin=25&seed=3
```

| 인자 | 기본 | 설명 |
|---|---|---|
| `text` | MERRY CHRISTMAS | 나무에 쓸 글자(최대 40자) |
| `letters` | 8500 | 글자 수. 가지마다 글자가 하나는 있어야 해서 하한(97)이 있고 더 작은 값은 하한으로 올립니다 |
| `lights` | 170 | 전구 수 |
| `spin` | 15 | 초당 회전 각도(도, 음수는 반대 방향) |
| `seed` | 7 | 같은 값이면 항상 같은 나무 |
| `paused` | | 값과 상관없이 있으면 정지 상태로 열고 첫 장면만 그립니다 |

## 만드는 방식

1. **가지**: 층(9개)마다 가지를 방사형으로 뻗습니다. 아래층일수록 가지가 많고, 층마다 각도를 황금비(0.618)만큼 어긋나게 돌립니다.
2. **글자**: 가지마다 점을 뿌립니다. 끝쪽에 더 몰리고, 끝으로 갈수록 처지며, 옆으로 퍼집니다. 점 하나가 글자 하나입니다.
3. **자라기**: 줄기에서 가깝고 꼭대기에 가까운 글자부터 10초 동안 늘어납니다(453개에서 시작).
4. **명암**: 가까울수록 밝고, 줄기 쪽은 어둡고 가지 끝은 밝습니다. 군데군데 반짝이는 잎이 있습니다.
5. **장식**: 다 자라면 황금 줄이 위에서부터 감기고, 장식 공이 나타나고, 전구가 하나씩 켜지고, 별이 빛납니다.
6. **그리기**: y축 회전 → 원근 투영 → 깊이 정렬 → 스프라이트 찍기.
   - 글자를 프레임마다 `fillText`로 그리면 느려서, 글자 × 색조 × 밝기 단계의 스프라이트를 미리 만들어 `drawImage`로 찍습니다.
   - 깊이 정렬은 계수 정렬(O(n))입니다. 먼 것부터 그려 가까운 글자가 위에 덮입니다.
   - 앞쪽 전구·줄만 가산 혼합으로 은은하게 번지게 하고, 뒤쪽은 잎에 가려집니다.

## 테스트

브라우저(Chromium)를 실제로 띄워 검사합니다. [Playwright](https://playwright.dev)가 필요합니다(이 프로젝트의 의존성으로 선언하지는 않았습니다).

```bash
cd web
npm test        # 문법 검사 → 브라우저 테스트 30개
```

- 난수·글자 수 배분·가지 모양·성장·전구/줄/장식 시점·투영·깊이 정렬·눈·HUD·URL 인자·컨트롤·창 크기 변경 같은 로직
- 화면 검사: 픽셀을 읽어 초록(나무), 황금(줄), 빨강(공), 별 빛이 자라는 시점에 맞게 나타나는지, 같은 시각은 항상 같은 그림인지
- 문법 오류가 있으면 브라우저 테스트가 타임아웃으로 줄줄이 실패해 원인이 가려지므로, 먼저 인라인 스크립트 문법만 따로 검사합니다(`scripts/check-syntax.mjs`).
- 다른 파일을 검사하려면 `XMAS_HTML=/경로/index.html npm test`

## 한계

- **성능은 GPU 있는 실제 브라우저에서 재 보지 못했습니다.** 이 환경의 헤드리스 Chromium(소프트웨어 렌더링)에서 1000×800, 글자 8,500개 기준 프레임당 약 34ms였습니다. 보통의 PC 브라우저는 더 빠를 것으로 예상하지만 확인한 값은 아닙니다. 느리면 ⚙에서 글자 수를 줄이세요.
- HiDPI는 최대 2배까지만 키웁니다(더 키우면 느려집니다).
- Safari 등 Chromium 이 아닌 브라우저에서는 확인하지 않았습니다.
- 영상 원본의 정확한 색감·가지 모양·장식 위치는 스크린샷으로 짐작한 값입니다.
